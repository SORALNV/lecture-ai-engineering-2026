## 宿題

### 取り組んだレベル

実装：`app/ask.py` を改修し、会話履歴を保ったまま続けて質問できるようにした。

### やったこと

1. 元の `ask(question)` と単発 CLI を維持し、`--chat` を追加した。
2. 対話では、成功したユーザーの質問とモデルの回答をメモリに保存し、次の質問と一緒に `generate_content` へ渡すようにした。
3. `/reset` で履歴を消去し、`/quit`、`/exit` または入力終了で対話を終了するようにした。空行では API を呼ばない。
4. API エラーや回答本文のない応答は履歴に残さず、利用者が改めて入力できるようにした。自動再送は行わない。
5. 入力・出力のトークン数を表示し、値がない場合には `取得不可` と表示するようにした。
6. API に接続しない単体テストと CLI テストを追加した。

### 気づき・疑問

会話履歴を保持するとは、前の回答を画面に残すだけでなく、次の API リクエストにも
以前の質問と回答を渡すことだと分かった。`role` を付けて発話の順番を保つことで、
「それを詳しく」のような続きの質問に必要な文脈を送れる構造にした。

一方、履歴をすべて送ると入力トークン数が増え、コンテキスト長や利用枠の制限に近づく。
そのため、今回は明示的に履歴を消せる `/reset` を用意した。長い対話では、履歴の要約や
古いターンの切り捨て方も検討する必要がある。

テストのダミー応答を実モデルの観察結果として扱わないことも重要だと考えた。
今回確認できたのは履歴を正しい形式で渡すプログラムの動作であり、
実モデルが文脈を正しく解釈して答えるか、実環境のクオータや通信が正常かは未確認である。
